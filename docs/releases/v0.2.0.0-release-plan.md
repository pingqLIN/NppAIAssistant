### 7.4 Why this automation change is required

舊流程有兩個 package producers：

```text
scripts/package-npp-ai-plugin.ps1
        -> ZIP A

CI tag workflow + 7z
        -> ZIP B
```

即使檔案內容相同，ZIP A / ZIP B 的 bytes、layout 或 SHA-256 都可能不同。新流程改成：

```text
build x64 Release
      |
      v
package-npp-ai-plugin.ps1
      |
      v
canonical ZIP (once)
      |
      +--> verify / schema / hash
      |
      v
workflow artifact (same bytes)
      |
      v
GitHub Release (same bytes)
      |
      v
re-download + SHA-256 verify
```

這是本次 release preparation 最重要的供應鏈修正之一。

Correction：ordinary CI no longer publishes Release ZIP；`release.yml` owns canonical packaging and promotes the same artifact bytes。

Severity：**MEDIUM**  
Old PR template used `NppAIAssistant Contributors` while project metadata/current official entry use `pingqLIN`。

Correction：draft template and submission guide now use `pingqLIN`。

### Finding D — RC schema validation vs final release URL

Severity：**MEDIUM**  
A pre-release RC may not yet have a direct GitHub Release ZIP URL；treating direct ZIP as a schema requirement would produce a false failure。

Correction：schema helper always validates official schema shape；`-RequireDirectHttpsZip` is a separate final-submission policy check。Tag release additionally performs real public download/hash verification。

### Finding E — Worktree branch mapping ambiguity

Severity：**MEDIUM**  
Earlier draft used a local `-prep-local` branch but later commands pushed `release/v0.2.0.0-prep`，which could confuse handoff agents。

Correction：SOP / plan now prefer a local tracking branch with the exact remote name；temporary branches must push explicitly with `HEAD:<remote-branch>`。
